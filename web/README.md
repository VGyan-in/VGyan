# VGyan Teacher Dashboard

React + TypeScript + Vite dashboard for teachers, researchers and administrators. All data comes from the VGyan backend (`backend/`); there is no bundled sample data.

## Run

```bash
npm install
echo "VITE_API_BASE_URL=http://localhost:8000" > .env.local
npm run dev
```

| Script | What it does |
|---|---|
| `npm run dev` | Dev server with HMR |
| `npm run build` | Typecheck (`tsc -b`) and production build to `dist/` |
| `npm run lint` | Oxlint |
| `npm test` | Vitest + Testing Library (auth, role-based views, student details, notes, research export) |

## Roles

| Role | Sees |
|---|---|
| Teacher | Only students in classes an admin assigned to them: overview, support list, students, reading and writing attempts (transcripts, word-level errors, original audio and handwriting via short-lived signed URLs), missed words, notes, passages and class assignments |
| Researcher | Research export only: de-identified, consent-filtered CSVs generated by the server. No named records |
| Admin | Everything above for all classes, plus schools, classes (join codes), staff accounts and data-deletion requests |

Staff sign in at `/auth/staff/login`. The token is kept in `sessionStorage`, so it is cleared when the tab closes (suits shared school computers). Create the first admin on the server with `python -m app.cli create-admin`.

## Data shown

Every number on screen is computed from synced attempts. The "needs support" flag (last three readings average below 75% accuracy) is a prompt for a teacher's attention, not a validated screening cut-off. Attempts whose metrics the server could not reproduce from the transcript are marked "not verified".

## Deploy

`.github/workflows/web-deploy.yml` builds the dashboard and publishes it to GitHub Pages on pushes to `main` that touch `web/`. Set the repository variable `VITE_API_BASE_URL` (Settings → Secrets and variables → Actions → Variables) to the backend URL, and add the Pages origin to the backend's `CORS_ORIGINS`.
